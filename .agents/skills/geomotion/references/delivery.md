# Stage-aware media delivery

Default delivery is a **direct MP4 URL**, opened with the browser's native video controls. `defaults.json` → `delivery.format` and `reuse_player` express this agent workflow policy; they do not add a direct-mode flag to the existing player CLI. Reuse the existing Sites hosting under `../delivery-target.json`, resolving its project ID through Sites before writing. Preserve audience and use the Sites skill for credentials, source synchronization and deployment. Credentials never belong in the repo. A missing checkout can be restored from that Site; do not create a duplicate. The binding is replaceable and supplies no story content.

## Direct MP4 delivery

Publish one compact current-stage file under a revisioned filename and return its literal HTTPS file URL ending in `.mp4`. Save that URL and file hash in the active work-state record. No custom UI, landing page, quality selector or new player assets are required. Leave existing player files and working historical links intact unless their removal is requested. Extra playback qualities are optional and must not trigger new derivation/QA/upload work unless requested; the preset quality arrays remain available to explicit player/variant workflows.

Stage rules below still apply. Check encoded dimensions/fps, duration, audio and source identity, stage the verified bytes without re-encoding merely for upload, then publish the exact pushed source through native Sites tools. Verify the direct asset's response/content type and, when available, byte count/hash against the local file. Keep source credits, license details and provider attribution metadata in private project `SOURCES.md`. Automatic visual credits remain off unless explicitly requested through scene `text_policy.source_credits`; source records do not certify rights or factual authenticity. Browser controls and seek behavior depend on the browser and host; a direct link does not reduce MP4 size or add the optional player's Range fallback. See [pipeline.md](pipeline.md#direct-mp4-delivery-default) for staging/provenance and current implementation limits.

## Editing / preview

Before final export is requested, composition, camera, VO, subtitle and asset revisions use **360×640 / 24fps**. Deliver the verified preview MP4 directly and record its preview stage. Do not pre-render unavailable higher qualities or silently show an old deliverable as the current edit.

After an explicit final request, retain **1080×1920 / 30fps** for revisions of that active production. Adding graphics, correcting layout or requesting another revision does not reset the stage or require another final request. Return to preview-only delivery only when the user asks. A lower-resolution diagnostic may be used for a specific check, but it must not replace the active final or become the current published revision by default. Retain stage/profile in the project work-state record described in [pipeline.md](pipeline.md#active-project-save-and-load); a new production starts with its own stage.

## Final

An explicit final request authorizes **1080×1920 / 30fps**, rendered directly from scene geometry, original imagery/assets and native text/subtitle composition. Never upscale a 360p or 720p preview. Directly encode the deliverable as compact H.264/yuv420p with AAC and faststart using `defaults.json` → `export.final`. Do not first create a large master and then recompress it. Do not create or publish a master download unless separately requested. Lossy intermediate parts should be minimized; if segmentation is needed for resources, assemble only needed sources once and use the same compact delivery settings at the final encode.

After final exists, deliver its compact **1080p MP4** directly. If lighter playback is requested, derive it from the verified final rather than rendering the scene again.

## Optional player, only when requested

The retained player can offer compact **360p / 1080p** files permitted by the preset. Final defaults to 1080p, with exactly one download action following the selected quality. No separate preview/master downloads, chunked master fetch, exposed technical metadata or unavailable quality placeholders. Its requirements below apply only to that explicitly selected player workflow.

Lower-quality playback follows `defaults.json` → `export.preview`. Use faststart, preload none and playsinline. The reusable player uses a transparent, accessible tap target for play/pause without a central play icon. Keep separate bottom controls for play/pause, elapsed/total time, mute and supported fullscreen. Its timeline supports tapping, pointer/touch dragging and keyboard seeking; seeking must not toggle playback, snap back during dragging or lose a requested position before metadata loads. Resume after dragging only if playback was active. Keep native controls as a fallback until custom controls initialize. Keep title, stage, duration, file size, quality selector and one download. Public credit content is optional and requires an explicit request; keep raw project source records private. Do not fetch the whole file on initial page load or when merely changing metadata; media loading may begin after a playback or seek interaction. Preserve the current playback position and play/pause state on quality changes. Use revisioned filenames and no-store manifest reads to avoid stale revisions.

Check the hosted MP4's response to byte-range requests. On the first seek, the player probes `bytes=0-0`: a `206` response keeps direct playback, while a host returning the whole file with `200` is handled by buffering that response into a local Blob URL. The selected time and play/pause state survive the source change; later seeks reuse the Blob. The first seek on a host without Range support may wait for the compact file to finish downloading. Abort outdated requests and release Blob URLs when changing quality. Report unavailable browser/device QA honestly.

## Reuse, verify and publish

`scripts/prepare_delivery.py VIDEO --stage preview|final --output SITE/dist --title TITLE [--narrated] [--credits PUBLIC_CREDITS.md]` preserves an existing UI (installs the template only when missing), checks native input resolution/fps, prepares the allowed compact variants and writes `media.json`. Use `--refresh-player-template` only for an explicitly intended UI replacement. Pass `--credits` only for explicitly requested, curated public credit content; do not publish private `SOURCES.md` automatically. It does **not** publish. The [pipeline](pipeline.md) adds review-bound preparation, encoded-variant QA and exact-commit handoff to native Sites tools. Call it on the verified, already compact final or the current 360p preview. Review high-motion smoke/texture legibility if bitrate settings need a justified scene-specific adjustment; a precise fixed filesize is not guaranteed.

Before publishing, complete relevant [quality checks](quality.md). For a player, validate manifest stage/dimensions and every listed file; return its deployed page URL only when that player was requested. Otherwise use direct-MP4 staging and return the verified file URL. Both require actual Sites publication; neither an edited manifest nor a copied local file publishes itself. Continue the configured publication workflow after verification without making the user repeat the instruction. This rule does not authorize YouTube or social publication.

## Efficiency

Use 360p before the first final request and retain the final profile afterward. Apply the [composition-first edit decision](pipeline.md#composition-first-edit-decision) before choosing an export: load the saved composition, reuse a still/current deliverable when sufficient, then reuse verified assets/audio/native segments and update only affected ranges under [revision reuse](pipeline.md#revision-reuse). Keep unchanged video segments free of additional lossy encoding when streams and joins are compatible. Skip player preparation and extra qualities for direct delivery. Prefer the cheapest checks that verify the actual risk, with one full decode of a new assembled deliverable; do not repeat unchanged checks or poll jobs unnecessarily. Fewer repeated operations can reduce agent work, but render time is not a measurement of Codex quota and no quota-saving percentage is guaranteed.

Only two delivery resolutions are enabled: 360p for editing/light playback and compact native 1080p for final. Never render, derive or upload a 720p intermediate or player variant by default. The 720-wide internal design coordinate grid is unrelated to export resolutions and remains valid.

Portable raw/source ZIPs must stay below 20 MB for the user's upload workflow. Preserve editable scenes, narration, stems, subtitle cues, assets and provenance; omit reproducible exports and caches first. Verify archive integrity and actual size. This is a packaging requirement, not a claim that a universal packager exists.
